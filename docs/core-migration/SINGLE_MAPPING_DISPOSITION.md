# 阶段 2 映射处置：三段式总则

用户于 2026-10-28 明确批准；本文件是 G02/G05/G06 复核的权威口径，取代旧审计中整包拒绝的处置描述。实现与源码证据另行提交，不以本文声称实现已完成。

## 总则原文（以 dual 的实际消费为准）

① dual 消费、single 有入口 → 正常映射；
② dual 消费、single 无入口 → 字段为非空/非默认值时显式拒绝（归既有错误分类、点名字段），默认值时放行；
③ dual 同样不消费（既有同病）→ 与 dual 同行为 + FEATURE_MAP 登记，不拒绝、不声称保留。
附则：内核写死的值（如固定 ALPN），存量值与写死值相同按等价放行并标注，不同按 ②。

## G02

Trojan gRPC 的 alpn=h2 与 pin 版 mihomo gRPC 的内核固定值相同 → 按附则放行并在落点表标注等价，不得拒绝；WS 固定 ALPN 同理，先从源码引用其固定值再逐值核对；存量值与固定值不同才按 ② 拒绝；alpn 为空当然放行。指纹条件消费逐条件对 dual，落 ③ 的不拒绝。

## G05

VLESS ws-headers 仅含 Host 且存在被消费的等价落点 → 转落该处并标注；含其他自定义头才拒绝。WG 无显式 peers 时，顶层 allowed-ips 落到隐含单 peer 实际消费的位置（同数据换落点属转换），加测试锁死；只有能证明两处语义不同，才改按 ② 并附证明。

## G06

逐子项出命运表，禁止整包拒绝：每个子项先核对 dual 的实际消费——dual 读而 single 有入口未映射的，补映射（①）；dual 读、single 无入口的，非默认按 ②；dual 也不读的，按 ③ 同行为加登记、不拒绝。TUIC 分支歧义先核对 dual 的确定性解析口径，dual 能定解的 single 不许以“歧义”拒绝。
